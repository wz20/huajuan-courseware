# 从参考课提取交互

选一个学生需要分辨的差别，直接翻到相应小节。各节的第一段记录参考课的可观察设计；“制作”和“验收”是把它用于新主题的原创实现建议。六种做法可以组合，单次活动通常只需一种主操作。

## 比较两次运行经过哪里 · Designed to Scale

**观察。** 缓存课把请求路线、命中率、数据库负载和分步解释放在同一组教学步骤中。节点有稳定位置，学生可以把注意力留给变化的路径。[参考课程](https://designed-to-scale.vercel.app)

**制作。** 固定节点和坐标。用事件记录“谁向谁发出什么、何时处理完成”；用同一个步骤游标决定已走过的路径和当时的计数。动画只在两个事件之间插值。讲图书借阅查询时，第一次查书经过书库并写入缓存，第二次查同一本书时缩短路线。保留累计查询次数给学生核对。

**验收。** 第一遍书库访问次数为 1，第二遍仍为 1。倒退到写入缓存前，缓存和计数同时回到当时状态。暂停动画时也能从图上读出当前位置。

## 看清输入如何变成输出 · Learn Arduino

**观察。** 旋钮课把模拟输入、PWM 输出、灯和串口监视器放在一起。模拟采样和输出指令有各自的数值范围；旋钮、程序、读数之间的这层转换值得保留。[参考课程](https://learn-arduino-red.vercel.app)

**制作。** 在实体的操作部位接受拖动或键盘输入。将输入交给一次模型计算，分别渲染原始值、中间换算和可见输出。把对应的规则或代码行放在读数旁。高频拖动按显示帧更新；需要留历史时，在一次拖动结束时记录。新例可用展柜调光器：让学生判断“旋钮一半，显示的两个数也一样吗？”

**验收。** 给定线性映射 0–1023 到 0–255 并四舍五入，输入 512 时两处显示 512 和 128。拖动与键盘调到同一位置，灯态一致；转动相机不会改变采样值。

## 分清指令和设备反馈 · Learn ESP32

**观察。** Wi-Fi 课从手机发出切换请求、让开发板改变灯态；智能车位把传感器、现场信号灯和手机看到的车位状态放在一堂课里。[参考课程](https://learn-esp32.vercel.app)

**制作。** 题目涉及两个端点时，分别画出发令者、执行者和反馈。新例“馆内呼梯”可把按键请求、轿厢到层和面板回报分成三个事件。学生在请求后暂停，预测哪两处应该还没变。如要教延迟或断连，用显式事件安排到达时刻，让课堂能重演同一次延迟。

**验收。** 只按呼梯键时面板显示等待、轿厢仍在原层；抵达后现场先变；回报到达时面板才更新。重复点击、回退或重置时可解释每个端点的状态。

## 认出当前工具，接着上一步做 · Backcountry 101

**观察。** 同一营地场景里，步骤会把提示锚到当前器材。灭火阶段又拆成几次可辨认的动作，旁边可以切换步骤、解释、提示。轮廓线使相似材质的工具易于辨认。[参考课程](https://backcountry-101.vercel.app)

**制作。** 每步定义所需工具、进入条件、实际动作和动作后留在场景里的变化。标注跟随物件的空间锚点；进入下一步时保留已加工的对象。新例“装订小册”：对齐纸页、夹住、穿线。选错工具时，在相关物件上解释缺少的条件。选择画风时先比较投影上两个工具的轮廓和接触位置。

**验收。** 未夹稳时穿线不会改变作品；完成穿线再回一步，夹子仍在，线迹消失。旋转视角后标注继续指向夹子。学生看完提示后仍由自己完成动作。

## 在实物上选位置，用原理图解释结果 · Electronics 101

**观察。** 万用表课把档位、插孔、探针接触点纳入测量。实物与电路图让学生从两个角度看同一连接关系。[参考课程](https://electronics-101-six.vercel.app)

**制作。** 给接点、部件和可测量的连接分配稳定 ID。从实物点选或图上点选都提交同一个 ID；先计算有效连接，再把路径、读数和实物高亮分别画出来。可迁移到轨道道岔：一边是俯视轨道，另一边是连通图。学生切换岔尖、选一个出口，判断列车能否从入口到达。

**验收。** 切到支线后，两视图同时高亮入口到支线的路径；选正线时显示不连通。转动、缩放或切换视图时，选择和连通结果保持一致。精确点不中小部件时，用同名按钮也能完成测量。

## 暂停并拆开一个正在传递的对象 · Protocol Explorer

**观察。** 网络图逐包播放；检查器可以查看选中包的内容，还可以切到前一个或后一个包。学生既能追踪消息去向，也能检查具体这条消息携带什么。[参考课程](https://protocol-explorer-alpha.vercel.app)

**制作。** 每个事件记录稳定 ID、对象 ID、发送端、接收端和该时刻的字段快照。时间游标表示播放到哪里；选中 ID 表示学生在查哪一条。打开详情时暂停，把现场标记、事件列表和字段高亮绑定到同一事件。新例“包裹转运”：同一包裹两次扫描，分别显示当时的站点和状态。

**验收。** 从列表和路线图选择同一次扫描，两处字段一致。选中第二次扫描后再查第一次，旧记录仍显示旧站点。两个不同包裹经过同一站时能分开检查。

## 在新课程里落地

- 用一句预测题决定第一屏。例如“馆内呼梯”如果要讲网络延迟，就让学生在“请求已发”和“设备已到”之间停住；如果要讲不同楼层的路线，就保留楼层位置，让学生逐步比较两次路径。同一主题可以选不同机制。
- 一次只呈现能区分预测结果的证据。接点要看方向和遮挡时用可旋转的实物 3D；讲消息先后时把位置和时间轴固定；讲有序操作时把当前可用的工具留在现场。视觉风格随观察任务选择。
- 要让老师回退并改换条件，可在 lesson.json 开启 `"history": true`，使用随包的 `createLessonHistory(initialState, reduce)`。状态放普通可复制数据，渲染对象和相机保留在视图中。调用 `act(action)` 提交一个教学动作，`back()`、`forward()`、`reset()` 返回可直接绘制的快照。无效动作在 reduce 中返回 undefined。持续变化的参数可以直接重新计算；快照适合学生能指出起止的离散动作。
